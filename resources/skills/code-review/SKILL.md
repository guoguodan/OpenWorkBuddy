# 代码审查

只读技能。不要修改任何文件,不要运行命令。

## 输出结构

1. **必须修复**(会导致错误行为、数据损坏、安全漏洞)
2. **建议修复**(可维护性、性能、一致性)
3. **可以忽略**(风格偏好)

每条必须包含:`文件:行号` + 问题 + 为什么 + 怎么改。

## 检查顺序

1. 边界条件:空值、零长度、越界、并发。
2. 错误处理:异常是否被吞掉、是否有重试但没有上限。
3. 资源泄漏:句柄、连接、定时器是否都有关闭路径。
4. 安全:路径拼接、命令拼接、凭据硬编码。

## 禁止

- 不要泛泛地说"建议增加测试",要指出具体缺哪个用例。
- 不要为了让报告好看而虚构行号;不确定就写"未定位"。
