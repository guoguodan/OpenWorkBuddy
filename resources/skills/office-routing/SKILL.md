# Office 任务路由

用户提到 docx / xlsx / pptx / 表格 / 汇报材料 时,按下面的顺序判断,不要直接开始写代码。

## 1. 先确认三件事

1. **输入在哪**:原始数据是文件、目录,还是用户口述。若在文件里,先 `glob` 定位,再 `read_file` 读样本。
2. **产物形态**:是新建一份文件,还是修改已有文件。
3. **下游消费者**:谁打开它、要满足什么格式约束(模板、页数、列名)。

任一项无法从上下文判断时,先问一个问题,不要猜。

## 2. 再决定技术路线

| 任务 | 首选 | 备选 |
|---|---|---|
| 批量生成 docx | 模板 + 变量替换 | 逐段拼装 OOXML |
| 结构化表格 | xlsx 库直接写单元格 | 先写 CSV 再转换 |
| 汇报材料 | 先出大纲,再逐页填内容 | 一次性生成完整 deck |

## 3. 交付前自检

- 产物能被目标软件正常打开(不是"看起来像")。
- 文件名不以点开头,不含空格与中文标点。
- 数值列不含千分位字符串。
- 用 `present_files` 收尾,让用户能直接点开。
