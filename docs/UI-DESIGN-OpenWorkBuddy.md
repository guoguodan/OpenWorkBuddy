本文档记录界面重构后的设计令牌与布局规则。所有数值都来自对 WorkBuddy 渲染层 CSS 的实测读取(tokens / contexts / src-CyXHA0IC 等文件),不是估算值。

## 1. 设计基调

| 维度 | 结论 |
|---|---|
| 主色 | 薄荷绿 `#00c29a`(品牌 8 号),hover `#40d1b3`,按下 `#009273` |
| 中性色 | 灰阶 `#fafafa → #e6e6e6`,暗色 `#141414 → #3a3a3a` |
| 圆角 | 卡片 8/12,弹层 16,输入框 24,按钮与胶囊 9999 |
| 字体 | 系统字体栈,正文 14px / 行高 22px,聊天正文 15px / 1.75 |
| 密度 | 会话列表项 34px 高、图标按钮 32px、模式胶囊 28–32px |
| 动效 | 160ms(交互)、260ms(布局),标准曲线 `cubic-bezier(.4,0,.2,1)` |

`WorkBuddy` 的界面语言是「低饱和中性底 + 一处品牌绿强调」:大面积留白、极细边框、几乎无阴影,只有输入框和弹层带阴影。这套语言是本次改造的核心。

## 4. 关键组件规范

### 4.1 模式分段控件(欢迎页)

- 轨道:`--owb-bg-tertiary`,圆角 9999,内边距 2px,`inset 0 0 0 .5px` 描边
- 选中项:白底 + `--owb-shadow-segment`,字重 600
- 未选中:hover 仅变底色,不改字重
- 图标 16px,与文字间距 6px

### 4.2 紧凑模式胶囊(会话输入框内)

- 高度 28px,字号 13px,未选中文字为三级色
- 与 WorkBuddy 的 `cr-mode-selector__trigger` 一致:文字优先、图标弱化

### 4.3 输入框(composer)

- 外层渐变底 + 24px 圆角 + composer 阴影
- 编辑器:15px / 1.75 行高,`textarea` 自适应高度(上限 200px)
- 工具行:左侧模式胶囊,右侧发送键
- 发送键:品牌绿胶囊,32px 高,禁用时 50% 透明
- 运行中:发送键替换为「执行中」,不可重复提交

模型胶囊打开后是一个真实菜单,候选来自当前 `OPENAI_BASE_URL` 网关的 `/v1/models`:

- 首次打开才拉取,展示“正在读取网关模型清单…”加载态,不阻塞输入框
- 候选只列网关真实返回的模型;当前值不在清单时明确标注,而不是伪造候选项
- 拉取失败时显示具体原因,同时保留下方自定义模型输入,网络不可用也能继续工作
- 每个候选是 `role="menuitemradio"`,当前模型带勾选态;选择后立即写回设置并进入下一轮请求

设置面板提供「备用模型」,与主模型共用同一条可信约束:

- 仅当主模型重试耗尽、且本步尚未输出任何文本或工具调用时才会切换;
- 已产生输出的回复绝不中途换模型,避免重复文本与重复副作用(如重复写文件);
- 切换后本轮后续步骤沿用备用模型,不会在两个模型之间来回跳;
- 对话页出现「主模型不可用,已切换到备用模型」提示,并同时显示两个模型名;
- 清空备用模型即关闭降级;与主模型同名的值不会产生额外请求。

降级只改变本轮实际使用的模型,不修改用户的主模型选择;助手消息与 trace 记录真实使用的模型名。

第三方服务连接面板(“更多”中的我的邮箱 / 腾讯文档 / ima / 乐享)遵循同一原则:界面不伪造连接结果。

- 提交后由 daemon 实际探测服务地址,默认总时限 5 秒,超时不会无限等待;
- 先发 HEAD;若服务拒绝 HEAD(405/501 等),在同一时限内改用 GET 复核;
- 仅 2xx/3xx 判定为「已连接」;401/403 显示要求身份验证,404 显示地址不存在,429 与 5xx 显示暂时不可用,网络错误、证书错误和超时都转成可读原因;
- 客户端上报的 `connected` 与 `lastError` 不被采信,状态只来自本次探测;
- 地址只保存 `protocol//host`,查询串、令牌、账号密码不会落库;含内嵌凭据的地址直接判为「连接地址无效」;
- 失败时卡片显示「连接异常」和具体原因,按钮仍可重新提交或断开。

### 4.4 消息

- 用户消息:右对齐,浅灰气泡,`16px 16px 0 16px` 圆角
- 助手消息:左对齐,无气泡,正文直接铺排(与 WorkBuddy 一致)
- 助手上方显示角色名「OpenWorkBuddy」,用户显示「我 · 模式名」
- 流式输出时末尾显示「正在思考…」

### 4.5 工具调用

- 单行紧凑条:状态图标 + 工具名 + 摘要(单行省略)
- 运行中旋转,成功绿勾,失败红叉

### 4.6 Markdown

自实现轻量渲染器(`src/lib/markdown.tsx`),全程 React 文本节点,不使用 `innerHTML`:

- 支持:标题、有序/无序列表、引用、分隔线、代码块(带语言标签)、行内代码、粗体、斜体、链接、表格
- 不支持:HTML 内嵌、脚注、数学公式(后续按需扩展)

### 4.7 会话头部(面包屑与任务菜单)

只有当前会话已有消息时才显示头部,避免在欢迎页凭空出现一条"任务"标题。

- 面包屑:`工作区 / 场景(模式) / 会话标题`,整体单行省略;悬停展示完整路径
- 标题就地重命名:点击菜单「重命名」后当前标题变为输入框,`Enter` 提交、`Esc` 取消、失焦提交;空标题不提交
- 右上箭头是真实按钮(`aria-haspopup="menu"` / `aria-expanded`),不是装饰性图标
- 菜单项:重命名、置顶/取消置顶、删除任务;点击菜单外部或按 `Esc` 关闭
- 置顶文案由当前会话 `pinnedAt` 驱动,操作后侧栏排序与菜单文案同时刷新
- 任务运行中禁用「删除任务」,并在悬停提示"结束后才能删除",避免删掉正在写入的会话
- 删除后界面回到会话空态,侧栏移除该条目;daemon 侧仍保证至少存在一条默认会话

标题来源遵循"系统标题 + 用户标题"分离:自动标题只写入系统标题,用户手动重命名后不再被首轮自动标题覆盖。

## 5. 可访问性与交互细节

| 项 | 做法 |
|---|---|
| 键盘 | `Enter` 发送,`Shift+Enter` 换行,输入法组合态不误发 |
| 焦点 | 搜索胶囊与输入框 focus 时显示 1px 品牌描边 |
| 语义 | 模式控件用 `role="tablist"` / `role="tab"` / `aria-selected` |
| 可读性 | 图标按钮均带 `title` 与 `aria-label` |
| 滚动 | 消息区自动滚底,用户手动上滚后不再强制吸底 |
| 侧边栏 | 折叠后仅留图标,带过渡动画 |

## 6. 与 WorkBuddy 的差异(有意为之)

| 项 | WorkBuddy | OpenWorkBuddy | 理由 |
|---|---|---|---|
| 品牌 | 自有 Logo 与字体 | 文本 Logo + 渐变色块 | 不复制品牌资产 |
| 会话列表 | 多分组 + 云任务 + 标签页 | 单列最近会话 + 搜索 | 当前数据模型只有会话 |
| 交付面板 | 右侧产物面板 | 会话头部交付物入口 + 右侧面板 | 数据模型与交互对齐,详情见第 8 节 |
| 扩展槽 | 微前端 federation | 无 | 当前无插件 UI |

## 7. 会话级交付物面板

真实产品把一次任务产出的成果当成独立对象集中查看,而不是只留在消息流里。OpenWorkBuddy 在会话头部提供「交付物」入口,右侧展开面板;面板属于当前会话,切换会话时随历史重新加载。

| 项 | 做法 |
|---|---|
| 入口 | 头部右侧 `交付物` 按钮,带数量徽标,再次点击收起 |
| 布局 | `owb-main__split` 左右分栏,面板宽 340px(窄屏 300px),不遮挡消息 |
| 搜索 | 匹配标题、描述、路径与链接 |
| 筛选 | 全部 / 文档 / 网页 / 图片 / 链接,显示各类型数量 |
| 打开 | 复用 `artifact.preview`:本地文件在工作区内解析,外链需二次确认 |
| 复制路径 | 复制 `path` 或 `url`,失败时给出系统提示 |
| 定位 | `artifact.reveal` 复用预览解析做越界与存在性校验后调用 `shell.showItemInFolder` |
| 重命名 | 只改数据库展示标题,不动磁盘文件名;Enter 提交、Esc 取消、失焦提交 |
| 移除 | 二次确认文案明确"文件仍在工作区";只删除 artifact 记录 |
| 空态 | 区分"还没有交付物"与"没有匹配的交付物" |
| 刷新 | 标题等记录从 `conversation.history` 恢复,不做前端伪持久化 |

## 8. 验收

### 全局搜索(Ctrl+K)

搜索一次覆盖四类实体,分组顺序固定,每组最多展示 5 条并保留完整命中总数:

| 分组 | 检索字段 | 点击后行为 |
|---|---|---|
| 消息 | 消息正文(FTS5 + 中文 LIKE 兜底) | 切到所属任务并滚动高亮该条消息 |
| 交付物 | 标题、路径 | 切到所属任务 |
| 任务 | 任务标题 | 切到该任务 |
| 项目 | 项目名称、简介、项目指令(仅当前工作区) | 打开项目面板,滚动到目标卡片并短暂高亮 1.8s |

项目命中不伪造会话跳转:`SearchHit.projectId` 是唯一定位键,`conversationId` 为空。
实时流里的消息在落库前没有 `seq`,因此同会话跳转会先同步一次历史,确保目标可定位。

验收:`node tests/e2e/verify-search-projects.mjs`(13 项)与 `node tests/e2e/verify-p7-4-ui.mjs`(9 项)。
